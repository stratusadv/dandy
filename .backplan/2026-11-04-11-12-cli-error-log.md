# CLI error log with line cap

- Developer: Nathan Johnson (nathanj@stratusadv.com)
- Status: Executed
- Date: 2026-11-04-11-12

## End State
When the CLI hits an error, a timestamped entry with the full traceback is
appended to `<project>/.dandy/logs/errors.log`, and the file is trimmed to the
newest 10000 lines after each write; `just test` (hermetic), `ruff check`/`ruff
format`, and `just lint-imports` are all clean.

## Observable Concern
The top-level catch added to `main()` must not change the existing exit-code
semantics (0/1 paths asserted in `test_main.py`) and must let the
`SystemExit` raised by `check_or_create_settings` on fresh setup pass through
unlogged.

## Current State
Verified facts:
- `DandyCli.process_agent_input` (`dandy/interfaces/cli/cli.py:219-221`) catches
  `Exception` from an agent turn and prints `Dandy ran into an error` — nothing
  is logged; the traceback is lost.
- `DandyCli.run_init` (`dandy/interfaces/cli/cli.py:274-276`) catches
  `Exception` and prints `Init failed` — nothing logged.
- `session_name_for_request` (`dandy/interfaces/cli/cli.py:28-37`) swallows all
  exceptions silently (falls back to the request text).
- `main()` (`dandy/interfaces/cli/main.py`) has no top-level catch: any startup
  or REPL-loop crash prints a raw traceback to stderr and exits 1, unlogged.
- `RunStoppedError` (escape-twice stop) is user-initiated, not an error.
- `DANDY_LOCAL_DIRECTORY_NAME = '.dandy'` (`dandy/shared/constants.py:31`);
  `ensure_dandy_gitignore` already ignores the whole `.dandy/` in git projects,
  so a `logs/` subdir is covered.
- `session.project_base_path` (`dandy/application/agent/session.py`) is the
  project root; interfaces may import shared, so a CLI-local module using
  `pathlib` + shared constants needs no new import-linter seam.
- No error-log utility exists; stdlib `logging` is only used by recorder events
  and the book example.
- **Pre-existing breakage (not from this work):** 3 tests in
  `tests/interfaces/cli/test_cli.py` fail on the clean tree — they expect
  `error='Coding agent failed'` but the code has printed
  `error='\nDandy ran into an error'` since commit 14d8e80.

Assumptions (flagged, correct me on approval if wrong):
- "Errors" = exceptions: agent-turn failures, init-pass failures, swallowed
  session-naming failures, and any unhandled crash (startup or REPL loop).
  UX-level messages (unknown command, missing session) are not logged.
- "Last 10000 lines ish" = hard cap: after each append the file is rewritten
  keeping at most 10000 lines, newest kept.
- Log location is per-project: `<project>/.dandy/logs/errors.log`.

## Deviations
1. The "stale" test cause was re-attributed during execution.
    - What: the plan said the code changed the error message since commit 14d8e80; in fact HEAD still says `Coding agent failed` and the `\nDandy ran into an error` message is part of the uncommitted WIP in the working tree. The fix direction (align tests to the current working-tree message) was unchanged.
    - Why: `git diff` against HEAD showed the message change was uncommitted WIP, not a landed commit.
2. Fixed two pre-existing ruff violations in files this plan already touches.
    - What: `FURB110` in `cli.py` (`name or request_text`) and `ARG001` x3 in the `fake_turn` test helper (`del` of the unused mirror parameters); both existed at HEAD, and `ruff check .` is a CI gate.
    - Why: the touched files had to be lint-clean for the completion test; both fixes are behavior-preserving.
3. Trim bug found and fixed during step 1 verification.
    - What: Python 3.13's `traceback.format_exception` returns elements that can embed a newline (File line + source line in one element), which broke the per-element `rstrip` line splitting; switched to `''.join(...).splitlines()`.
    - Why: the trim test observed 10001 lines instead of exactly 10000 until the fix.
