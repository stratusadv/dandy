## Current State
- `QuestionTool.handle(question, choices)` parks via `question_gate.ask(question, choices, stop_signal)`; `QuestionGate.ask` has no notion of a sequence; the TUI prints `Asking` + `↳ <question>` (`tui.get_user_input(question=..., choices=...)`).
- `Printer.run_timed_task`: on a pending question it settles beats, `pause_at_fresh_line()`, prompts, `deliver`, `drop_live_frame()` — then the loop animates only once a new beat arrives; the placeholder beat that animates from request start is never reused after a question, so no thinking animation while the model thinks post-answer.
- `skills_banner_line` (`banner.py`) lists up to 10 mixed skills as `N loaded (A active, P passive): names`.
- `ActivateSkillTool` has no `action_label`/`action_output` — its beat falls back to title-cased `Activate Skill` with no detail.
- Wording: `Started a new conversation.` / `...to be saved as "name".` in `cli.py::_process_new`; `activate_skill`/`Activate` in `domain/skill/prompts.py` and `SkillService` texts; skill result line `Skill "x" is now active.`
- `/sessions` prints the full table (`print_sessions`, no limit); no `/session-all` command exists; `CLI_COMMANDS` registry drives REPL dispatch, tab/suggestions, one-shot flags, and usage text.
- Welcome banner (`Printer.welcome`): `Model : <model>`, separate `AGENTS.md :` line; settings source path is not exposed (`settings._json_settings_path` exists for the JSON fallback; module path is reachable via `importlib`).
